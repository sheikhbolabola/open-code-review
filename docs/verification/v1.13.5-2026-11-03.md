# OpenCodeReview v1.13.5 fork upgrade verification

Date: 2026-11-03. Repository: `sheikhbolabola/open-code-review`.

## Decision

The fork is functionally compatible with stable v1.13.5 on Linux/amd64 under
Go 1.26.10 and Node.js 24.22.1. Functional tests passed, including the tracked
gitignored-file regression. The dependency audit is not completely clean:
the frontend development dependency tree has 21 affected package entries.
Keep the upgrade PR in draft pending review of these findings and the
unavailable deployment-specific checks below. No merge or main-branch update
was performed.

### Gitignore regression details

`internal/diff/workspace_gitignore_regression_test.go` tests directory, glob and
root-anchored ignore rules, plus a filename containing a tab. Each pattern is
tested with unstaged, staged, mixed staged/unstaged and deleted tracked changes.
Windows runs the 12 cases with legal filenames and explicitly skips the four
tab-filename cases, since that filesystem cannot represent those paths. The
complete diff race suite was rerun after adding this platform guard.
The provider must retain the tracked diff, retain ordinary untracked source,
omit ignored untracked source, and retain built-in dependency directory
exclusions for reporting. The test checks actual changed/deleted diff content.

The real CLI preview was independently exercised for the same 16 combinations.
Deleted files remain visible in the preview with the explicit exclusion reason
`deleted`; they are not independently reviewed under the existing allowlist
policy. This is different from silently losing a tracked modification because
its path matches `.gitignore`.

### Test environment issue resolved

The first root test and coverage runs failed
`TestInitOTLPHTTPProviders_HonoursBasePath`. The inherited
`OTEL_TRACES_SAMPLER=parentbased_traceidratio` could suppress the probe span.
The isolated telemetry suite, full root race suite and full coverage suite all
passed with `OTEL_TRACES_SAMPLER=always_on`. No repository telemetry code or user
configuration was changed to obtain this result. Reproduce the full runs with:

```sh
OTEL_TRACES_SAMPLER=always_on OCR_DELEGATE_REQUIRE_PTY=1 make test
OTEL_TRACES_SAMPLER=always_on OCR_DELEGATE_REQUIRE_PTY=1 make coverage
make check
make build
make -C acp test
make -C acp coverage
make -C acp check
```

## Security audit findings

- Root `govulncheck` 1.6.0: PASS at the called-symbol level, zero affected
  imported packages. It reports two module-level advisories in unimported
  `golang.org/x/net` functionality: [GO-2026-6866](https://pkg.go.dev/vuln/GO-2026-6866)
  and [GO-2026-6860](https://pkg.go.dev/vuln/GO-2026-6860). Both name 0.62.0 as
  the fixed version; the stable release requires 0.60.0. The scan does not
  prove the whole dependency tree is vulnerability-free.
- ACP `govulncheck`: PASS, no findings.
- Frontend `npm audit --omit=dev`: PASS, zero findings.
- Frontend `npm audit` including dev dependencies: FAIL, exit 1, 21 affected
  package entries (18 moderate, 3 low, zero high/critical). This is a package
  count, not 21 distinct CVEs. Findings include fast-uri, glob, minimatch and
  deepmerge, with propagation through the Jest/ts-jest test toolchain. Some
  automatic fix proposals downgrade Jest/ts-jest across major versions;
  those changes were not applied as part of the stable-release synchronization.

These are outstanding dependency findings, not functional regression failures.
Do not describe the combined audit as clean. Remediation should be reviewed
and tested separately before approving this draft for deployment.
